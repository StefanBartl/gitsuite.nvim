## Dashboard keys (component-local)

Not part of the table above — `:Git dashboard`'s own row/mark/batch/page
keys, set on its buffer only, declared in one table in
[`features/dashboard/view.lua`](../lua/gitsuite/features/dashboard/view.lua)
(which also generates the panel's `winbar` legend and the `?` cheatsheet,
so the three can't drift apart), moved here unchanged from reposcope.nvim's
former `:Reposcope dashboard`.

| Key | Mode | Action |
| --- | --- | --- |
| `<CR>`, `<2-LeftMouse>` | n | Confirm, then open the repository's `README.md`. `q` in the README returns to the dashboard on the same row |
| `m` | n, x | Toggle the mark on the row; in Visual mode mark every row the selection spans |
| `M` | n | Mark every repository, or clear all marks when everything is already marked |
| `p` / `P` / `f` | n | Push / pull (`--ff-only`) / fetch the marked repositories, or the row under the cursor when nothing is marked |
| `gp` / `gf` | n | Push / fetch **every** repository on the current page, marks ignored; `gf` fetches `dashboard.fetch_jobs` (default 4) at once, push stays one by one |
| `gP` | n | Pull the page, marks ignored: asks "Only behind" (repos behind their upstream) or "All"; repos with unknown behind state (no upstream, never fetched) are named. Default focus: `dashboard.pull_scope` |
| `gu` | n | Update every repository on the current page: `fetch --all --prune` + `pull --ff-only` |
| `S` | n | Full `git status --short` plus the last five commits, in a nested popup |
| `L` | n | Open `:Git ui lazygit` for the repository under the cursor |
| `s` | n | Cycle sort order: discovery → name → state (worst first) → last-commit age → discovery |
| `r` / `R` | n | Re-read the row under the cursor / re-scan the current page |
| `<C-l>`, `<Right>` / `<C-h>`, `<Left>` | n | Switch to the next / previous configured `dashboard.groups` page (see [configuration.md](configuration.md#dashboard)) |
| `a` | n | Add a repository or directory path to the current page (`vim.ui.input`), persisted outside `setup()` |
| `x` | n | Remove the repository under the cursor from the current page — never touches disk |
| `y` | n | Yank the repository's path |
| `?` | n | List every one of these keys |

Every batch (`p`/`P`/`f` with marks set, the `g` forms, and switching to a
page with no repositories yet) is confirmed or reported before it runs;
each push/pull/fetch/update runs through `lib.nvim.progress` (`progress_style`,
see [configuration.md](configuration.md)) so a statusline component can show
it, and re-reads just its own row afterwards rather than re-scanning the page.

A running batch does not lock the whole dashboard. Each repository in it is
`queued` (`· fetch queued`), in flight (`⟳ fetch...`), done, or failed
(`✗ fetch failed`), and the title counts how far the batch got
(`fetch 4/12`). A row the batch is done with (or failed on) takes `p`/`P`/`f`
right away, in parallel with the rest of the batch; a queued or in-flight row
refuses with a message. A lock per repository keeps two writing `git`
processes off the same repository. Sorting, re-scanning, page switches and a
second batch still wait for the running one.

## Plugins report keys (component-local)

The report tab of `:Git plugins` and `:Git plugins report` (`--out=tab`, the
default). Set on the report's list buffer only, declared in one table in
[`features/plugins/report_ui/keys.lua`](../lua/gitsuite/features/plugins/report_ui/keys.lua),
which also makes the `winbar` legend and the `?` list; a spec compares this
table with it, row by row. Some letters mean something else here than on the
dashboard (`p` is the preview, not push; `S`, `L` and `y` mean the same kind
of thing, for the clone under the cursor).

| Key | Mode | Action |
| --- | --- | --- |
| `<CR>` | n | On a plugin: its detail. On a commit in the digest: its plugin's detail, cursor on the commit |
| `<BS>` | n | Back to the overview |
| `D` | n | Breaking digest: the breaking commits of every plugin in one list |
| `s` | n | Cycle the sort: breaking first, name, number of commits, time of the update |
| `A` | n | List the unchanged plugins too, or count them again |
| `]]` / `[[` | n | Next / previous plugin's detail (in the overview's order) |
| `]b` / `[b` | n | Next / previous breaking commit not marked as seen |
| `m` | n | Mark the commit under the cursor as seen, or every new commit of the plugin under it; again: unmark |
| `M` | n | Mark every commit this view lists as seen |
| `o` / `K` | n | Open in the browser: the commit's page, or on a plugin the compare page of its update; what it shows counts as seen |
| `go` | n | Open the compare page of the plugin's update, also from a commit line |
| `gy` | n | Copy the URL `o` would open |
| `y` / `Y` | n | Copy the short / full hash (on a plugin: the commit its update ended on) |
| `L` | n | lazygit in the plugin's clone (lazygit can change the clone; the report itself never does) |
| `S` | n | The clone's git status and last five commits, read only |
| `C` | n | The plugin's CHANGELOG, in the tab the report was opened from |
| `Q` | n | The breaking commits into the quickfix list, opened in the tab the report was opened from |
| `F` | n | Jump to a plugin or a commit by name (picker) |
| `O` | n | Menu of the actions for the line under the cursor |
| `p` | n | Show or hide the preview (follows the cursor) |
| `q` | n | Close the report tab; the report stays, `:Git plugins` opens it again |
| `?` | n | List every one of these keys |

With a `plugins.summarize` hook, `plugins.summarize_key` (default `gS`) asks
for the AI summary of the plugin under the cursor; the plugin's detail shows
it, labelled as generated and not verified.

## Internal (not typed by hand)

`GitsuiteLazygitBadd`/`GitsuiteLazygitReplace` are lazygit's `O`/`<C-o>`
custom-command targets, called via `nvr` from inside lazygit's own process
-- see [docs/lazygit-config.yml](lazygit-config.yml). Registered directly
via `lib.nvim.bindings.usercmd`, outside the `:Git` tree and this generated
table, since nothing about them is ever typed by a person.
