# Health check

`:checkhealth gitsuite` runs four sections in order.

## gitsuite

| Line | Means |
| --- | --- |
| ✅ `lib.nvim detected (:Git command layer available)` | `lib.nvim.bindings.usercmd.composer` resolved — the `:Git` command itself can register |
| ❌ `lib.nvim not found -- :Git will fail to register` | A hard dependency is missing; install `StefanBartl/lib.nvim` |
| ✅ `diff.nvim detected (:Git diff * available)` | `diff.nvim` resolved |
| ❌ `diff.nvim not found -- :Git diff * will fail` | The other hard dependency is missing; install `StefanBartl/diff.nvim` |
| ✅ `git executable on PATH` | `vim.fn.executable("git") == 1` |
| ❌ `git executable not on PATH -- gitsuite.nvim needs it for everything` | Nothing in this plugin works without a real `git` binary |

Both hard-dependency lines are reported as ❌ errors, never ⚠️ warnings —
neither has a fallback (see [requirements.md](requirements.md)).

## gitsuite: adapters

One line per adapter (`gitsigns`, `diffview`, `neogit`, `lazygit`,
`native`):

| Line | Means |
| --- | --- |
| ✅ `<name>: available` | That adapter's backing plugin/binary is present |
| ℹ️ `<name>: not available` | Absent — never a warning or an error. Every family with a native fallback (`native.lua`) keeps working; a family with no fallback (e.g. `ui neogit` without neogit) simply reports "not installed" when actually invoked, not here |

`native` is always ✅ inside a git repository — it needs nothing beyond
`git` itself, already confirmed above.

## gitsuite: plugin state

| Line | Means |
| --- | --- |
| ✅ `plugin loaded (vim.g.loaded_gitsuite = true)` | `:Git` has run at least once, or `setup()` was called directly |
| ℹ️ `plugin guard not set yet (...)` | Normal under `cmd = "Git"` lazy-loading before the first invocation — not a problem |

## gitsuite: setup() options

| Line | Means |
| --- | --- |
| ✅ `No unknown or invalid setup() options` | The last `setup()` call validated cleanly |
| ⚠️ one line per issue | An unknown key or a wrong-typed value was dropped; the built-in default is in effect for that key. See [configuration.md](configuration.md) for what each key actually accepts |

A trailing section (generated by
`lib.nvim.bindings.usercmd.composer.checkhealth`) reports the registered
`:Git` command name and route count — useful mainly after renaming the
command via `commands.git` (see [configuration.md](configuration.md)).
